# VibeCritic

منصة عربية مستقلة لاكتشاف الألعاب والأفلام والمسلسلات وقراءة مراجعات نقدية منظمة. تعرض المنصة تقييماً تحريرياً من 10، وتحليلاً للجوانب الفنية والتقنية عند توافر الأدلة، مع نقاط القوة والضعف والحكم النهائي، إضافة إلى مؤشرات الرواج وكتالوج ترفيهي قابل للبحث.

- **الموقع:** https://vibecritic.pages.dev/
- **المستودع:** https://github.com/manou23/VibeCritic-
- **التقنيات:** Astro 7، Tailwind CSS 4، Pagefind، Cloudflare Pages، D1، Pages Functions وDurable Objects.
- **لغة الواجهة:** العربية (RTL).

> الدرجات أحكام تحريرية خاصة بـ VibeCritic وليست متوسطات مواقع التجميع. لا تدّعي المراجعة اختباراً مباشراً أو مشاهدة شخصية ما لم يكن ذلك مثبتاً؛ وتُذكر حدود المعلومات عند نقص الأدلة.

## المزايا

- مراجعات للألعاب والأفلام والمسلسلات مع درجة من 10 ومحاور تقييم ونقاط قوة وضعف.
- صفحات منفصلة حسب نوع المحتوى وصفحات مراجعات مستقلة.
- بحث عربي في المراجعات المنشورة عبر Pagefind، مع تطبيع بعض اختلافات الكتابة العربية.
- كتالوج للأفلام والمسلسلات مدعوم بـ Cloudflare D1، مع بيانات العناوين والأشخاص والطاقم والأنواع وفهرس FTS5.
- مؤشرات رواج من مصادر البيانات، مع التمييز بين المراجعات المنشورة وروابط الاكتشاف الخارجية.
- أداة «المراجع الذكي» لإنشاء مراجعة بمساعدة نماذج الذكاء الاصطناعي، مع التحقق من بنية المخرجات وحدود الاستخدام.
- موجز RSS وبيانات وصفية وSitemap.

## هيكل المشروع

```text
.
├── .github/workflows/    # النشر المرحلي وفحوص الجودة ومزامنة البيانات
├── data/                 # حالة طابور المحتوى وبيانات العمل/المعرفة
├── functions/api/        # Cloudflare Pages Functions، ومنها review.js
├── migrations/           # مخططات SQL وترقيات D1
├── public/               # الأصول الثابتة
├── scripts/              # التوليد والتحقق والفهرسة والمزامنة والاختبارات
├── src/
│   ├── components/       # مكونات واجهة Astro
│   ├── content/reviews/  # المراجعات المنشورة بصيغة Markdown
│   ├── data/             # بيانات الموقع المولّدة، ومنها الترندات
│   ├── layouts/          # القوالب العامة، ومنها Base.astro
│   ├── pages/            # صفحات ومسارات الموقع
│   └── styles/           # أنماط CSS
├── astro.config.mjs      # إعداد Astro وPagefind وSitemap وعناوين النشر
├── package.json          # أوامر المشروع والاعتماديات
├── package-lock.json     # إصدارات الاعتماديات المقفلة
└── wrangler.jsonc        # إعداد Pages وD1 وDurable Objects
```

هذا مخطط للمجلدات والمسؤوليات الأساسية، وليس جرداً لكل ملف. قد تتغير الملفات الفرعية مع تطور المشروع.

## التقنيات ومصادر البيانات

- **Astro:** بناء الصفحات والمحتوى.
- **Tailwind CSS:** تنسيق الواجهة.
- **Pagefind:** فهرسة البحث المحلي في المراجعات.
- **Cloudflare Pages:** استضافة الموقع؛ ناتج البناء في `dist/`.
- **Cloudflare D1:** كتالوج الأفلام والمسلسلات وذاكرة بيانات المصدر.
- **Pages Functions وDurable Objects:** واجهة المراجع الذكي وحدود الاستخدام.
- **TMDb:** بيانات الأفلام والمسلسلات.
- **RAWG وIGDB:** بيانات الألعاب بحسب مفاتيح المصدر المتاحة.
- **YouTube:** إثراء بعض المراجعات بمقاطع رسمية عند توافرها.
- **مزودو الذكاء الاصطناعي:** Gemini وGroq وOpenRouter وOpenAI وCloudflare Workers AI بحسب الإعدادات المتاحة.

### إسناد البيانات

بيانات الأفلام والمسلسلات مقدمة عبر [TMDb](https://www.themoviedb.org/). يستخدم المنتج TMDb API لكنه **غير معتمد أو مصادق عليه من TMDb**. يجب عرض شعار TMDb وإشعار الإسناد المطلوبين والالتزام [بشروط TMDb](https://www.themoviedb.org/documentation/api/terms-of-use). قد تأتي بيانات الألعاب من [RAWG](https://rawg.io/) أو [IGDB](https://www.igdb.com/)؛ ولا تعني الإشارة إلى هذه الخدمات وجود شراكة أو اعتماد.

## التشغيل محلياً

يتطلب المشروع إصدار Node.js المحدد في `engines` داخل `package.json` (حالياً `>=22.23.4`).

```bash
git clone https://github.com/manou23/VibeCritic-.git
cd VibeCritic-
npm ci
npm run dev
```

للبناء والمعاينة:

```bash
npm run build
npm run preview
```

أمر البناء هو `npm run build` وناتجه `dist/`. في Cloudflare Pages يُضبط `CF_PAGES=1` لاستخدام مسارات الجذر وعنوان Cloudflare Pages؛ أما الإعداد الافتراضي المحلي فيهيئ الموقع لمسار GitHub Pages.

## النشر الآلي

يعمل Workflow **Generate reviews and publish** كل ساعة عند الدقيقة 17 بتوقيت **UTC** (أي الدقيقة 17 من كل ساعة؛ ويوافق ذلك الدقيقة 17 من الساعة التالية في الجزائر). يتقدم المقال المحفوظ عبر مراحل تحريرية منفصلة، ويُنتج جزءاً في التشغيل، ولا يُنشر إلا بعد اكتماله واجتياز التحقق. لذلك لا يعني كل تشغيل نشر مقال جديد.

تجري قبل النشر فحوص المحتوى والدرجات والبيانات الوصفية، ثم بناء الموقع والتحقق من ناتج البناء وSEO وSitemap. توجد مهام مستقلة لمزامنة كتالوج TMDb إلى D1 وفحوص الجودة. راجع ملفات `.github/workflows/` لمعرفة المشغلات والخطوات الفعلية؛ فقد تتغير الجداول مع تحديث المشروع.

### إعداد D1

اسم قاعدة الكتالوج `entertainment-db`، وربطها `ENTERTAINMENT_DB` في `wrangler.jsonc`. المخطط الأساسي في `migrations/0001_entertainment_catalog.sql`، وتوجد ترقية منفصلة لذاكرة المصدر في `migrations/0003_source_cache.sql`.

تحتاج المزامنة إلى إعداد `TMDB_READ_ACCESS_TOKEN` و`CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID` في إعدادات GitHub Actions. شغّل Workflow **Sync TMDB catalog to D1** يدوياً للتهيئة الأولى؛ ثم تتولى الجدولة الموجودة في ملف Workflow المزامنة الدورية.

### إعداد التوليد

يتطلب التوليد `TMDB_API_KEY`، ومصدر ألعاب واحداً على الأقل (`RAWG_API_KEY` أو `IGDB_CLIENT_ID` مع `IGDB_CLIENT_SECRET`)، ومفتاح مزود ذكاء اصطناعي واحداً على الأقل. تُحفظ المفاتيح في **Settings → Secrets and variables → Actions**، بينما تضبط خيارات المزود والنموذج وحدود الاستخدام عبر Repository Variables. تختلف المتطلبات الإضافية حسب الميزة وWorkflow؛ راجع الملفات الحالية قبل التهيئة.

**لا تضع مفاتيح API أو رموز الوصول أو ملفات الاعتماد في المستودع أو README أو Issues أو سجلات Actions.**

## الاختبارات والتحقق

أوامر التحقق والاختبارات معرفة في `package.json`. من أمثلتها:

```bash
npm run validate:reviews
npm run validate:build
npm run test:review-validation
npm run test:tmdb-sync
npm run test:catalog-api
npm run test:knowledge-graph
npm run test:editorial-reasoning
```

قد تحتاج بعض الاختبارات إلى إعدادات أو بيانات محلية؛ راجع الأمر المقابل داخل `scripts/`.

## الأمان

- خزّن مفاتيح الخدمات في GitHub Actions Secrets أو إعدادات Cloudflare فقط.
- تجاهل ملفات البيئة والمخرجات المؤقتة ومجلدات البناء باستخدام `.gitignore`.
- استخدم أقل الصلاحيات الممكنة لرموز Cloudflare وراجع صلاحيات GitHub Actions.
- فعّل **Secret Scanning** و**Push Protection** من **Settings → Code security and analysis** إذا كانت الميزات متاحة للمستودع والخطة.
- إذا تسرّب مفتاح، أبطله أو دوّره لدى مزود الخدمة فوراً؛ حذف السطر من آخر Commit لا يبطله ولا يزيله من تاريخ Git.

## الشفافية وجاهزية مراجعة الإعلانات

توثيق المستودع لا يضمن قبول الموقع في Google AdSense أو أي شبكة إعلانية؛ فالقرار يعتمد على الموقع المنشور ومحتواه وتجربة المستخدم والامتثال للسياسات، وليس README وحده.

قبل التقديم، انشر صفحات واضحة وسهلة الوصول لسياسة الخصوصية، والتعريف بالموقع والجهة التحريرية، ووسيلة تواصل، والإفصاحات اللازمة عن الإعلانات والكوكيز والبيانات. **القالب العام الحالي يعرض التنقل وRSS وإسناد مصادر البيانات، لكنه لا يعرض في تذييله روابط مستقلة لسياسة الخصوصية أو «من نحن» أو «اتصل بنا»**؛ لذلك يلزم استكمال هذه الصفحات وربطها في الموقع نفسه قبل اعتبار الجاهزية الإعلانية مكتملة. راجع أيضاً أصالة المحتوى وقيمته، وحقوق الصور والاقتباسات، وإيضاح دور الذكاء الاصطناعي.

مراجع رسمية: [سياسات برنامج AdSense](https://support.google.com/adsense/answer/48182) · [متطلبات خصوصية المستخدمين والإفصاح](https://support.google.com/adsense/answer/1348695).
